# Media helper-boundary feasibility prototype

This experiment compares the two authority models required by Phase 1 using the
same encrypted, chunked synthetic media object and the same supervised worker:

- `object-key`: the helper receives one random object DEK and authenticates each
  requested XChaCha20-Poly1305 chunk itself.
- `broker`: the supervisor retains the DEK, authenticates requested chunks, and
  returns plaintext chunks to the helper.

In both modes the worker receives no path, vault master/catalog/wrapping key, or
general directory access. Control, source data, and RGBA frames use a versioned,
length-bounded pipe protocol. Decoded frames cross back to the supervisor with
pipe backpressure; audio remains worker-owned. Appsrc, video, audio, and appsink
queues are bounded. The worker enables `no_new_privs`, disables dumpability and
core dumps, caps open descriptors at 32, and caps address space at 768 MiB.
Malformed initialization framing, inconsistent logical/chunk lengths, and
invalid chunk-response lengths are rejected by automated tests.

This is experiment framing, not the final `.osvo` or Phase 7 IPC format. It does
not yet deny networking or filesystem opens with seccomp/Landlock, pass object
descriptors with `SCM_RIGHTS`, render transported frames, lock/wipe all buffers,
or contain a compromised GPU/driver.

Install the exact Arch packages listed in the
[consolidated prototype prerequisites](../README.md).

## Run

Use the public synthetic fixture generated by the GStreamer prototype:

```sh
cargo test
cargo clippy --all-targets -- -D warnings
cargo run --release -- \
  --input /tmp/osv-phase1.ogv --mode object-key --exercise-restart
cargo run --release -- \
  --input /tmp/osv-phase1.ogv --mode broker --exercise-restart
```

Add `--real-audio` only for an interactive PipeWire check. Record elapsed time,
source requests/bytes, frame count/bytes, crash detection, CPU/RSS, and visible
or audible failures for both modes. Do not infer large-video behavior from the
small synthetic fixture.
